サイト別カスタマイズの進め方

BCP プラグインと BCP テーマはどのサイトでも同じものを使います。サイトごとの違いは、決められた2つの場所にだけ書きます。
このガイドは、one est のような新しいサイトを担当する方に向けたものです。WordPress の経験があれば読めるように書いてあります。

サイト設定

サイトごとの違いを入れる層です。「孫テーマ」は作りません（WordPress が対応していないため）。代わりに、テーマの中に用意された2つの置き場所を使います。

どのサイトとして動くかは、wp-config.php の1行で決まります。
define( 'VIP2026_SITE', 'one-est' );
テーマの functions.php がこの定数を読み、inc/sites/one-est.php を読み込みます。定数が無ければ jadeclinic として動き、'none' にすると何も読み込まない素のテーマになります。存在しない名前を書いても何も起きないだけで壊れません。

3

実際の手順

STEP 1環境をそろえる

サイトのフォルダには、テーマもプラグインも配信されてきた完成品が入っています。ここを git 管理する必要はありません。ソースはリポジトリ側にあります。

  • WordPress 管理画面で BCP プラグインとテーマを最新に更新する
  • wp-config.php に define( 'VIP2026_SITE', 'one-est' ); があることを確認
  • 「外観 → エディター → スタイル」で One Est が選ばれているか確認

STEP 2変更はリポジトリで行う

テーマのリポジトリを clone し、ブランチを切って作業します。触るのは styles/one-est.json と inc/sites/one-est.php の2つだけ。

# ブランチを切る（feat/ か fix/ で始める）
git switch -c feat/one-est-brand-color

# 触るのはこの2つだけ
styles/one-est.json
inc/sites/one-est.php

git add -A && git commit -m "feat(one-est): ..."
git push origin feat/one-est-brand-color

そのあと GitHub で Pull Request を出します。main へ直接 push はしません。

STEP 3手元で確認する

変更したファイルを、ローカルサイトのテーマフォルダへコピーして確認します。

cp styles/one-est.json \
   ~/DevKinsta/public/one-est/wp-content/themes/vip2026/styles/

注意: このコピーは確認用です。次にテーマの更新が来ると上書きされて消えます。必ずリポジトリ側にもコミットしてください。

STEP 4リリース

PR がマージされると、テーマのバージョンが上がり、Supabase から配信されます。各サイトの管理画面に更新通知が出るので、そこで更新すれば反映されます。サイトへ手作業でファイルを置く運用はしません。

4

やってはいけないこと

どれも「その場は動くが、次の更新で壊れる／他のサイトを巻き込む」ものです。

1. BCP プラグインのファイルを直接編集する
更新で消えます。しかも消えたことに気づくのは、たいてい公開後です。変えたい挙動は必ずフィルター経由で。フィルターが無ければ「フィルターを足してほしい」と依頼してください。
2. テーマ本体（vip2026 直下）を編集する
同じ理由で消えます。加えて、そのファイルは他のサイトでも使われています。one est のために変えた1行が、jadeclinic の表示を壊すことがあります。
3. サイトのフォルダごと git 管理する
テーマもプラグインもそれぞれ別のリポジトリで管理されているので、二重管理になって必ず食い違います。サイトのフォルダは「配信結果」であってソースではありません。
4. テーマをコピーして「one-est 用」を作る
いちばんやりがちで、いちばん後悔します。最初は楽ですが、本体が改良されても取り込めなくなり、半年後には別物になります。すでにその仕組みは用意されているので、必要ありません。
5. 管理画面のサイトエディターで直接デザインを変えて終わりにする
サイトエディターの変更はデータベースに保存されます。ファイルではないので、git に残らず、他の環境にも移りません。試作には便利ですが、確定したら styles/one-est.json に書き戻してください。
5

git の扱い

リポジトリは2つ。サイトのフォルダは含まれません。

github.com/showhey0705/jade-clinic-theme ← テーマのソース ├── styles/one-est.json one est の配色 ├── inc/sites/one-est.php one est の処理 ├── inc/sites/jadeclinic.php 他サイトの処理（触らない） └── ... テーマ本体（触らない） github.com/showhey0705/beauty-clinic-patterns ← プラグインのソース └── ... 全部触らない │ Supabase 経由で自動配信 ▼ ~/DevKinsta/public/one-est/ ← サイト。git 管理しない ~/DevKinsta/public/jadeclinic/ ← 同上
ブランチの決まり: main へ直接 push しません。feat/...（機能追加）か fix/...（修正）でブランチを切り、Pull Request を出します。作業が終わったブランチは削除してください。

コミットメッセージ: どのサイトの変更か分かるよう、feat(one-est): ... のようにサイト名を入れてください。
6

サロンで使うときの注意

BCP は美容クリニック（医療機関）向けに作られています。サロンは医療機関ではないので、逆向きの制約がかかります。技術より先に、ここを決めてください。

言葉が合わない

画面のあちこちに「施術」「症例」「院長」「診療時間」といった言葉が出ます。サロンでは「メニュー」「お客様の声」「オーナー」「営業時間」にしたいはずです。翻訳ファイルで差し替えられますので、プラグインは触らないでください。

使えない表現がある

サロンは医療行為をうたえません。「治療」「治る」「〇〇が改善します」といった表現は薬機法に触れる可能性があります。ビフォー・アフターの見せ方も、景品表示法の観点で書き方を変える必要があります。

  • 効果を断定しない（「〜が期待できます」も条件つきで注意）
  • 医療行為と誤認させる表現を使わない
  • お客様の声には、個人の感想である旨と条件を添える

BCP には医療広告ガイドライン向けのチェッカーが入っていますが、サロン向けの判定ではありません。文言のルールは別途決めてください。
